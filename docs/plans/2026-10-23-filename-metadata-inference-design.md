# 文件名元数据识别设计（月份 / 平台 / 国家）

> 日期：2026-10-23
> 状态：已确认，开发中
> 关联：`问题记录.md` →「文件名元数据识别」

## 1. 背景

海外数据批量上传时，一次可能上传 400 个文件。部分文件的 Excel 中没有「月份」和「平台（亚马逊/虾皮）」字段，逐个人工映射成本很高。

目标：

1. 从文件名识别月份、平台、国家。
2. 识别成功后，该文件所有行自动填充这些值，列映射中不再要求映射对应字段。
3. 识别失败时，仍按现有列映射方式从文件中取值。
4. 国家识别成功后回显到上传页国家选择器；识别失败则为空，由用户选择。
5. 国家必须是平台已配置且启用的国家。

## 2. 推荐文件名格式

### 2.1 标准格式

```text
{YYYYMM}_{平台}_{国家}_[{品类}]_{描述}.xlsx
```

示例：

```text
202609_amazon_US_[运动相机]_Fryers.xlsx
202609_shopee_MX_[路由器]_AirPurifiers.xlsx
2026-09_amazon-CA_[运动相机]_数据看板导出.xlsx
```

品类放在方括号里，避免品类码中的下划线被分隔符拆开。

分隔符支持：下划线 `_`、短横线 `-`、空格。

### 2.2 平台别名

| 文件名写法 | 标准值 |
|---|---|
| `amazon` / `amz` / `亚马逊` | `amazon` |
| `shopee` / `虾皮` / `西皮` | `shopee` |

### 2.3 国家写法

按 `countries` 表匹配，支持：

- ISO 国家码：`US`、`CA`、`DE`、`MX`
- 中文名：`美国`、`加拿大`、`德国`
- 英文名：`United States`、`Canada`（可选支持）

只识别 `is_active=1` 的国家。识别到但未启用/不存在的国家，视为未识别，并在界面提示。

### 2.4 月份写法

- `YYYYMM`：`202609`
- `YYYY-MM`：`2026-09`

统一转为 `202609`。

### 2.5 兼容现有文件名

除了标准格式，再增加一个宽松的 token 扫描：

- 把文件名按 `_`、`-`、空格拆成 token。
- 在 token 中查找月份、平台、国家。
- 某个字段出现多个候选值时，视为「歧义」，该字段不自动识别，要求映射。
- 示例：`副本20261008_Top100 202608_Fryers...` 同时出现 `202610` 和 `202608`，月份视为歧义，不自动识别。

> 推荐业务侧尽量按标准格式重命名 400 个文件，识别最稳定。

## 3. 识别结果

后端返回如下结构（前端用于展示）：

```json
{
  "month": 202609,
  "platform": "amazon",
  "country_code": "US",
  "country_name": "美国",
  "month_ambiguous": false,
  "platform_ambiguous": false,
  "country_ambiguous": false,
  "warnings": []
}
```

字段为空表示未识别。

## 4. 优先级与落库

### 4.1 月份 / 平台

- 文件名识别成功：**文件名优先**，覆盖 Excel 中映射出来的月份/平台。
- 文件名未识别：使用列映射从 Excel 取值。
- 如果文件名识别成功但 Excel 也映射了对应字段，界面提示「文件名识别将覆盖文件内字段」。
- 如果两处都没有：该文件标记「需手动」，不能批量确认。

### 4.2 国家

- 文件名识别成功：上传页国家选择器自动回显。
- 用户可以在上传页修改国家，**用户选择优先**于文件名。
- 文件名未识别：国家选择器为空，海外文件仍必须由用户选择。
- 后端最终使用上传请求里的 `country_code`；如果请求未传，才回退到文件名识别值。

### 4.3 全行填充

后端在写 `raw_data` 前，对每条记录执行：

```text
record.month = filename_month or mapped_month
record.platform = filename_platform or mapped_platform
record.country_code = resolved_country
```

去重键继续使用 `(country_code, item_id, month, platform)`，因此文件名识别的值会参与去重。

## 5. 必填字段校验调整

当前必填字段固定为：

```text
item_id, month, platform, item_name, sales_qty, sales_amount, price
```

调整后按文件计算：

```text
required = 固定必填 - 文件名已识别字段
```

例如：

- 文件名识别出月份和平台：映射中不再要求 `month`、`platform`。
- 只识别出平台：仍要求映射 `month`。
- 都没识别出：仍要求映射两者。

国家不是 Excel 必填字段，继续由上传页国家选择器控制。

## 6. 后端设计

### 6.1 新增文件名解析模块

`backend/app/services/filename_metadata.py`

职责：

- 输入原始文件名。
- 输出月份、平台、国家、歧义标记、警告。
- 国家校验依赖 `countries` 表。

### 6.2 `/upload/headers` 返回识别结果

在上传文件表头响应中增加：

```json
{
  "temp_file_id": "...",
  "filename": "202609_amazon_US_Fryers.xlsx",
  "columns": ["..."],
  "suggested_template": {},
  "filename_hints": {
    "month": 202609,
    "platform": "amazon",
    "country_code": "US",
    "country_name": "美国",
    "warnings": []
  }
}
```

前端根据 `filename_hints` 回显国家、展示月份/平台标签。

### 6.3 `/upload/confirm` 后端重新解析文件名

不依赖前端传值，后端根据 `original_filename` 重新解析，避免客户端绕过。

- 月份/平台：文件名值覆盖每一行。
- 国家：`payload.country_code` 优先，未传时使用文件名识别值。
- 必填字段校验按上面的动态规则。
- 回写 `upload_files.platform`、`upload_files.country_code`。
- 预览和结果中返回识别来源，便于排查。

### 6.4 识别失败/歧义

- 字段为空，不阻断上传。
- 前端标记「需映射」。
- 后端确认时如果发现缺失且映射也没有，返回 422，错误信息明确指出缺少的字段。

## 7. 前端设计

### 7.1 待处理文件列表

新增展示列：

- 识别月份：`202609` 或「需映射」
- 识别平台：`amazon（亚马逊）` 或「需映射」
- 识别国家：国家选择器，识别成功时预填，失败时为空

状态：

- 月份、平台都识别成功，或映射能补齐：`可批量`
- 任一缺失且映射无法补齐：`需手动`

### 7.2 列映射页

顶部展示只读标签：

```text
文件名识别：月份 202609 · 平台 亚马逊 · 国家 美国
```

- 识别成功的月份/平台字段仍出现在列映射表中，但不再作为必填项。
- 如果用户把文件列映射到已识别的月份/平台，提示「文件名识别优先，文件内该列将被忽略」。
- 国家显示在页面上方可修改。

### 7.3 批量确认

- 自动映射计算时，把文件名识别的月份/平台计入已满足字段。
- 因此即使 Excel 中没有月份/平台列，也可以显示「可批量」。
- 批量确认时把国家选择器和文件名识别结果一起提交。

### 7.4 400 个文件的交互

- 文件列表支持显示识别结果汇总：
  - 已识别月份：N
  - 已识别平台：N
  - 已识别国家：N
  - 需手动：N
- 可增加「仅看需手动」筛选，先处理异常文件。

## 8. 示例

### 8.1 标准文件名，Excel 没有月份/平台

文件名：

```text
202609_amazon_US_Fryers.xlsx
```

Excel 列：

```text
ASIN, 产品名称, Listing月销量, Listing月销额, 实际价格
```

系统：

- 月份 = 202609
- 平台 = amazon
- 国家 = US（回显）
- 映射只需 ASIN → item_id、产品名称 → item_name、销量/销额/价格。
- 所有行写入 `month=202609`、`platform=amazon`、`country_code=US`。

### 8.2 文件名未识别

```text
副本20261008_Top100 202608_Fryers.xlsx
```

同时出现 `202610` 和 `202608`，月份歧义，不自动识别；平台也没有识别出来。此时仍需在映射中提供月份和平台。

## 9. 边界与风险

1. 文件名中的随机 6 位数字可能误判为月份；出现多个候选时按歧义处理，不自动识别。
2. 平台/国家缩写可能与描述文本冲突；只做 token 级匹配，不做整串模糊匹配。
3. 国家识别依赖国家主数据，未启用的国家不会被回显。
4. 文件名识别值会覆盖 Excel 内同名字段，需要界面明确提示。
5. 400 个文件逐个读取表头仍然是 400 次请求，识别能力本身不改变这个耗时；后续可评估批量表头接口。

## 11. 品类识别（扩展）

需求方确认：品类仍然走分发规则，但把文件名识别出的品类作为一个新的「匹配字段」，能力和商品名称类似。

### 11.1 文件名格式

```text
YYYYMM_平台_国家_[品类]_描述.xlsx
```

示例：

```text
202609_amazon_US_[运动相机]_Fryers.xlsx
202609_amazon_US_[action_cameras]_Fryers.xlsx
```

- 方括号内可写品类码或中文品类名称。
- 通过 `categories` 表匹配，统一归一化为 `category_code + category_name`。
- 多个方括号或匹配不到品类时，品类为空，并提示未识别。
- 识别失败不阻断上传，只是该字段为空。

### 11.2 落库字段

`raw_data` 新增：

- `source_category_code`：文件名识别出的品类码
- `source_category_name`：文件名识别出的品类名称

这些字段只表示文件名来源，不替代分发规则最终写入的 `dispatch_items.category_code`。

### 11.3 分发规则匹配字段

「数据分发 → 编辑规则 → 匹配字段」新增：

- `文件名品类名称`
- `文件名品类码`

仍可选择 Lv0-Lv3 类目或商品名称，规则匹配后决定最终分发到哪个目标品类。

### 11.4 界面回显

- 待处理文件列表增加「识别品类」列。
- 列映射页顶部展示「识别品类：运动相机」等标签。
- 未识别或歧义时显示「未识别 / 歧义」，不要求列映射，因为品类不是 Excel 必填字段。

### 11.5 示例规则

目标品类：运动相机
平台限定：amazon
匹配字段：文件名品类名称
匹配方式：精准
匹配值：运动相机

这样文件名 `202609_amazon_US_[运动相机]_Fryers.xlsx` 的所有行都可以命中该规则。
