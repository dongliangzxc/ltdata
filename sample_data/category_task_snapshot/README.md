# 品类任务快照验证数据

## 文件

- `jd_category_snapshot_batch1.xlsx`：4 行，京东格式；2 行回音壁 + 2 行路由器，月份 202605。
- `jd_category_snapshot_batch2.xlsx`：2 行，京东格式；1 行回音壁 + 1 行路由器，月份 202606。
- `seed_categories_dispatch_rules.sql`：可选种子 SQL，用于创建 `soundbar` / `router` 品类和按 Lv2 类目分发的规则；规则值支持用 `/`、`、`、`,` 分隔多个候选值。

## 推荐验证路径

1. 如环境没有对应品类/分发规则，先执行 `seed_categories_dispatch_rules.sql`。
2. 在“数据上传”上传 `jd_category_snapshot_batch1.xlsx`。
3. 到“数据分发”对该文件执行分发。
4. 在分发统计里应看到：
   - 回音壁：当前批次 2 条，待创建任务 2 条。
   - 路由器：当前批次 2 条，待创建任务 2 条。
5. 对“回音壁”创建清洗任务。
6. 到“清洗任务”列表，应看到新任务；点击“进入处理”进入“清洗任务详情”。
7. 再上传并分发 `jd_category_snapshot_batch2.xlsx`。
8. 回到第一批创建的回音壁任务，验证其原始/清洗后数量仍是第一批快照数量，不会自动包含第二批新增行。
9. 在第二批分发统计里，应看到回音壁还有 1 条待创建任务。
10. 若第一批任务可发布，发布前应提示“该品类另有 1 条新增数据尚未创建任务，不会随本次发布”。

## 说明

这些样例用于验证任务快照和待处理池，不追求真实匹配率。若型号库没有对应型号，任务详情中可能进入待确认队列，这是正常的。
