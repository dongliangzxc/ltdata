## 2. 本次要验证的规则

| 项目 | 预期 |
|---|---|
| 周次含义 | 用户提供的月内第几周，结合业务月份使用；系统不计算日期 |
| 合法值 | 数字1～5，或字符串`"1"`～`"5"`；首尾空格可去除 |
| 数字与文本一致性 | 数字3、文本`"3"`、文本`" 3 "`均表示同一月份第3周 |
| Excel数值3.0 | 接受并归一化为3 |
| 不合法的写法 | `第3周`、`W03`、`03`、文本`3.0`、全角数字、布尔值、小数、0、6等 |
| 周度空值 | 提示补齐，不按月度偷偷入库 |
| 月度数据 | 周次为空，原有月度流程继续可用 |
| 不同周 | 同商品同月不同周分别保留 |
| 同一周 | 重复上传按原规则跳过，不重复增加销量 |
| 月报与周报 | 可以分别保存和查询，不自动相加、不自动生成完整月报 |

页面显示“第3周”是展示标签；文件内请填写数字3或文本`"3"`。

## 3. 必测流程

请按以下顺序测试，便于核对预期数量。首次使用应是全新验收数据；重测时可重启本地验收脚本。

### T01：一次上传5周，验证数字与字符串

1. 打开“数据上传”，选择`01_周度_五周数字和字符串.xlsx`。
2. 待处理行的数据粒度应显示“周度”；周次选择留在“从文件周列读取”。
3. 国家选择“中国（CNY）”。
4. 标记为“可批量”时，点击“批量确认入库”；也可通过“配置映射”核对后确认。
5. 映射应包括month→月份、week→周次、platform→平台、item_id→商品ID，其余标准列按同名字段映射。
6. 上传完成后，查看写入数量与上传历史。
7. 到“原始数据”，选择周度、月份209901，查询测试商品。

**预期：** 写入5条、跳过0条；平台显示京东，上传历史显示第1～5周。相同商品`WEEKLY-ACCEPT-A`保留5条，各周1条。

| 周次 | 销量 | 销售额 |
|---|---:|---:|
| 1 | 10 | 1000 |
| 2 | 20 | 2000 |
| 3 | 30 | 3000 |
| 4 | 40 | 4000 |
| 5 | 50 | 5000 |

### T02：分发并创建5个周任务

1. 打开“数据分发→分发管理”，对T01成功上传的文件执行分发，品类选择耳机。
2. 打开“清洗任务”，选择耳机、周度、月份209901。
3. 待入队列应出现第1～5周共5行，每行1条。
4. 勾选5行，点击“批量创建/追加任务”，等待完成。
5. 在下方任务列表查看结果；选择某个周次，应只显示该周任务。

**预期：** 共5个独立周任务，每个任务输入1条、清洗后1条，任务名称包含正确周次。不会生成一个包含5周的月度任务。

### T03：同周重复上传

1. 上传`02_周度_重复上传.xlsx`，仍选周度、从文件周列读取、中国。
2. 查看入库结果，再查询209901周度原始数据。

**预期：** 写入0条、跳过5条；周度原始数据仍为5条。此重复文件无需再次分发。

### T04：第2周新增数据追加到原任务

1. 上传`03_周度_第2周追加.xlsx`。
2. 查看结果：其中A商品第2周已存在，B商品第2周是新增。
3. 对本文件执行耳机分发。
4. 打开清洗任务，选择209901、第2周，点击“追加到任务”。
5. 核对任务ID及其他周任务数量。

**预期：** 上传写入1条、跳过1条；第2周沿用原任务，输入/清洗后数量由1变为2。第1、3、4、5周仍各1条。

### T05：月度与周度同商品共存

1. 上传`04_月度_同商品.xlsx`，粒度选择“月度”，无需周列。
2. 执行耳机分发，到清洗任务切换“月度”，选择209901并创建任务。
3. 分别查询月度与周度原始数据、清洗任务。

**预期：** 月度新增1条A商品，不与A商品的各周记录冲突。新增1个独立月度任务；月度筛选只显示月报，周度筛选只显示周报。

### T06：文件没有周列，手动指定第3周

1. 上传`05_周度_手动指定第3周.xlsx`。
2. 在待处理行把粒度改为“周度”，周次选择“第3周”。
3. 选择国家后确认入库，再执行耳机分发。
4. 到第3周队列追加到原任务。

**预期：** C商品写入第3周；第3周原任务输入/清洗后数量由1变为2。不会按月度入库，也不会根据当前日期改变周次。

### T07：在第2周任务内补充数据

1. 在第2周已有任务行点击“补充数据”。
2. 选择`06_补充_目标任务继承周期.xlsx`。
3. 确认弹窗展示目标为209901第2周，提交。
4. 观察新增/重复数量及任务结果。

**预期：** 文件没有月份、周次，继承目标任务209901第2周。A商品跳过1条，D商品新增1条。第2周任务输入/清洗后数量由2变为3，其他周不变。

在正式后台任务测试环境，还应先人工确认原任务中的一条记录，再执行补充或追加，核对原记录的型号、属性、人工备注及发布关系保留。本地同步预览建议先完成全部追加，再进行人工确认和发布。

### T08：补充文件周次冲突

1. 仍在第2周任务中点击“补充数据”。
2. 选择`07_补充_周次冲突.xlsx`，文件明确填写第1周。
3. 提交后查看提示。

**预期：** 提示文件周次与目标任务不一致，不增加原始数据、文件记录或任务输入数量。第2周仍为3条。

### T09：不合法的周次

1. 依次上传`invalid/`中的文件，每次选择“周度”和中国。
2. 周次选择保持“从文件周列读取”，确认入库。
3. 查看提示，然后移除该待处理文件，继续下一个。

**预期：** 每个文件都提示第2行周次不符合规范或缺少周次，不生成成功入库的数据。覆盖0、6、小数、`第3周`、`W03`、`03`、文本`3.0`、空值、布尔值和全角数字。

测试过程中修正原文件后可重新上传，不必删除已通过的其他周数据。

### T10：分发核对与导出

1. 打开“分发结果下载”，选择周度、209901、耳机、京东，仅选第2周并创建导出任务。
2. 下载文件，检查月份、周次、商品ID及销量。
3. 切换月度，使用相同月份、品类、平台再导出。
4. 打开“规则命中核对”，分别按第1周、第2周及月度查看。
5. 在“数据导出”页分别导出第2周清洗结果和月度结果。

**预期：** 周度第2周导出A、B、D共3条，销量分别20、7、9；月度导出仅1条A，销量150。周度文件明确展示周次，月报不混入周报。导出任务保留当时的周期条件。

补充上传沿用现有流程，直接归入任务，不重新命中常规分发规则，因此“规则命中核对”中第2周常规规则命中数为2；分发结果与清洗范围包含补充来源时为3。规则核对与任务总量的这一差异不属于串周。

### T11：发布后不同周互不覆盖

1. 完成前面的追加/补充，再分别进入第1周、第2周任务的匹配处理页。
2. 本地预览已预置匹配规则，测试数据应匹配到“周度验收型号”；确认可发布后点击“发布到分析库”。
3. 打开“查询工作台”，选择2099年、209901、周度，分别选择第1周、第2周查询。
4. 再发布同一第2周任务，重新查询。
5. 发布月度任务，再分别查询月度和周度。

**预期：** 第1周保留1条A；第2周保留A、B、D共3条。重复发布第2周数量仍为3，不增加重复行、不覆盖第1周。月度发布后，月报仍单独保留；规格属性属于对应周期的记录。

其他测试环境若未自动匹配，可先人工指定有效型号再发布。尚未发布的其他周不会出现在查询工作台中。

## 5. 可选补测

## 7. 本地重启和正式测试环境准备

本地预览服务关闭后，可在项目根目录重新运行：

```bash
backend/.venv/bin/python scripts/weekly_acceptance_preview.py
```

默认端口8006。端口被其他程序占用时可追加`--port 8007`。重启会创建全新临时验收数据，不修改之前的数据目录。

前端代码变化后，需先在frontend目录执行`npm run build`。测试样例可通过`backend/.venv/bin/python sample_data/weekly_cases/generate.py`重新生成。

正式测试环境需要：升级数据库到`p82a1b2c3d4e5`，同步更新API、清洗worker和前端产物，再按本文验收。迁移会为存量增加月度标识并保留原始周字段；历史库已有年内周不会被自动改成月内周。原始表若因历史重复而没有唯一约束，沿用p65兼容策略：保留全部旧记录和应用层查重，扩展非唯一查重索引；无历史重复时建立含周次的唯一约束。发布表仍须满足周期唯一约束，重复则阻止迁移；已有周度数据时禁止直接降回旧月度唯一约束。
